## Fast version

```julia
"""
    Bodies(pos, vel, mass)

N-body state in struct-of-arrays layout: one contiguous vector per coordinate.
`pos` and `vel` may be given as vectors of length-3 vectors or as 3×n matrices.
"""
struct Bodies{T<:AbstractFloat}
    x::Vector{T}
    y::Vector{T}
    z::Vector{T}
    vx::Vector{T}
    vy::Vector{T}
    vz::Vector{T}
    m::Vector{T}
    function Bodies{T}(x, y, z, vx, vy, vz, m) where {T<:AbstractFloat}
        n = length(m)
        all(v -> length(v) == n, (x, y, z, vx, vy, vz)) ||
            throw(DimensionMismatch("all coordinate vectors must have length $n"))
        return new{T}(x, y, z, vx, vy, vz, m)
    end
end

function Bodies(pos::AbstractMatrix, vel::AbstractMatrix, mass::AbstractVector)
    size(pos, 1) == size(vel, 1) == 3 || throw(DimensionMismatch("pos and vel must have 3 rows"))
    T = float(promote_type(eltype(pos), eltype(vel), eltype(mass)))
    col(A, k) = Vector{T}(A[k, :])
    return Bodies{T}(col(pos, 1), col(pos, 2), col(pos, 3),
                     col(vel, 1), col(vel, 2), col(vel, 3), Vector{T}(mass))
end
Bodies(pos::AbstractVector{<:AbstractVector}, vel::AbstractVector{<:AbstractVector}, mass::AbstractVector) =
    Bodies(reduce(hcat, pos), reduce(hcat, vel), mass)

positions(b::Bodies) = [[b.x[i], b.y[i], b.z[i]] for i in eachindex(b.m)]
velocities(b::Bodies) = [[b.vx[i], b.vy[i], b.vz[i]] for i in eachindex(b.m)]

"""
    step!(b::Bodies, dt)

Advance one time step (same scheme as before: accelerations from the current
positions, then `vel += acc*dt`, then `pos += vel*dt`). Each pair is visited
once and its equal-and-opposite contributions are applied to both bodies.
Does not allocate.
"""
function step!(b::Bodies, dt)
    x, y, z, vx, vy, vz, m = b.x, b.y, b.z, b.vx, b.vy, b.vz, b.m
    n = length(m)                       # the constructor guarantees every vector has length n
    for i in 1:n
        xi, yi, zi, mi = x[i], y[i], z[i], m[i]
        dvx = dvy = dvz = zero(eltype(m))
        # i+1:n ⊆ 1:n for all seven vectors. Bounds checks here block SIMD; with
        # them removed this loop runs ~4× faster (measured at n = 1000).
        @inbounds @simd for j in i+1:n
            dx = x[j] - xi
            dy = y[j] - yi
            dz = z[j] - zi
            r = sqrt(dx^2 + dy^2 + dz^2 + 1e-9)
            s = dt / r^3
            sj = m[j] * s
            dvx += sj * dx
            dvy += sj * dy
            dvz += sj * dz
            si = mi * s
            vx[j] -= si * dx
            vy[j] -= si * dy
            vz[j] -= si * dz
        end
        vx[i] += dvx
        vy[i] += dvy
        vz[i] += dvz
    end
    for i in 1:n                        # positions move only after every velocity is updated
        x[i] += vx[i] * dt
        y[i] += vy[i] * dt
        z[i] += vz[i] * dt
    end
    return b
end
```

Usage, converting from the original layout:

```julia
b = Bodies(pos, vel, mass)       # pos, vel: Vector{Vector{Float64}} (or 3×n matrices)
for _ in 1:nsteps
    step!(b, dt)
end
pos, vel = positions(b), velocities(b)   # back to vectors of 3-vectors, if needed
```

## What changed, and why

1. **No allocation.** The original allocates for every pair: `pos[j] - pos[i]`, `d .^ 2`, `mass[j] * d`, `/ r^3`, and the `+=` on `acc[i]` all create new 3-element arrays, plus the `acc` array itself. That came to 10⁷ allocations (381 MiB) per step at n = 1000. All arithmetic is now on scalars, and the accelerations are added straight into the velocities, so no `acc` buffer is needed. This is valid because `vel` does not affect the accelerations, and `pos` is updated only after every velocity has been updated, which is the same scheme as the original. The test checks `@allocated step!(b, dt) == 0`.
2. **Each pair once (Newton's third law).** The force between `i` and `j` is computed once and applied to both bodies, with opposite signs and weighted by the other body's mass. This halves the number of `sqrt` and division operations. `dt` is folded into the scale factor `s = dt / r^3`. As a side effect, total momentum is conserved to rounding error, which is tested.
3. **Struct-of-arrays layout.** `x, y, z, vx, vy, vz, m` are each a contiguous `Vector`, so the inner loop over `j` reads and writes consecutive memory in every array. The original's `Vector{Vector{Float64}}` stores each body as a separate heap object reached through a pointer.
4. **`@inbounds @simd` on the inner loop only, and measured before keeping it.** At n = 1000, the same SoA loop took 2.78 ms with bounds checks and 0.67 ms without them. The checks prevent vectorization, and a 3×n-matrix version without the annotation took 2.55 ms. Every array has length `n`, which the inner constructor enforces, and `j ∈ i+1:n`, so the indices are provably in range. The tests also pass with `--check-bounds=yes`. `@simd` allows the `dvx/dvy/dvz` sums to be reordered. The `vx[j]` stores go to a different `j` on each iteration, so they do not depend on one another.
5. **Floating-point differences only.** Pair contributions are summed in a different order and `dt` is applied per pair, so the results differ from the original only by rounding. After 10 steps the maximum difference in positions and velocities was below 1e-12 for n ≤ 257 (tested).

## Timings (measured, BenchmarkTools, Julia 1.13, one thread)

| n | original | `step!` | speedup |
|---|---|---|---|
| 100 | 829 µs (100,002 allocs) | 8.9 µs (0 allocs) | 94× |
| 1000 | 96.2 ms (10,000,003 allocs) | 0.67 ms (0 allocs) | 144× |
| 10000 | — | 65.0 ms (0 allocs) | |
