## Faster version

```julia
"""
    pairwise_dist_fast(X::AbstractMatrix)

Euclidean distances between the rows of `X` (n×d), as an n×n matrix.
For d < 16 the result is bitwise identical to `pairwise_dist`; for larger d
it differs only by rounding (`sum` switches to a reassociated SIMD reduction
at 16 elements).
"""
function pairwise_dist_fast(X::AbstractMatrix)
    Base.require_one_based_indexing(X)
    d = size(X, 2)
    # Small d: make it a compile-time constant so the inner sum is unrolled.
    return d < 16 ? _pairwise(X, Val(d)) : _pairwise(X, d)
end

function _pairwise(X, dim)
    n = size(X, 1)
    pts = [ntuple(k -> X[i, k], dim) for i in 1:n]   # contiguous points
    T = typeof(sqrt(zero(eltype(X))))
    D = Matrix{T}(undef, n, n)
    Threads.@threads for j in 1:n                   # each task owns whole columns
        D[j, j] = zero(T)
        pj = pts[j]
        for i in j+1:n                               # lower triangle, down column j
            D[i, j] = sqrt(sqdist(pts[i], pj))
        end
    end
    # Mirror: (a - b)^2 == (b - a)^2 exactly, so D[i, j] == D[j, i] bit for bit.
    Threads.@threads for j in 2:n
        for i in 1:j-1
            D[i, j] = D[j, i]
        end
    end
    return D
end

# Left-to-right, the order `sum` uses for fewer than 16 elements.
function sqdist(a, b)
    s = zero(eltype(a))
    for k in eachindex(a, b)
        t = a[k] - b[k]
        s += t * t
    end
    return s
end
```

## Changes, and why each one helps

1. **No temporary arrays.** `X[i, :]` copies a row, then `.-` and `.^2` each allocate another array, so the original makes 4 allocations for every one of the n² = 4×10⁶ pairs: 24 million allocations and 946 MiB in total. The new version accumulates `t*t` in a scalar loop and allocates nothing in the hot loop.
2. **Contiguous points.** In `X`, a row is strided in column-major order. Each point is copied once into an `NTuple{d}` (`pts`), so reading a point is a single contiguous load.
3. **The dimension is a compile-time constant.** `Val(d)` makes `d` (3 here) part of the type, so `sqdist` is unrolled into three subtract-multiply-add steps with no loop overhead. On one thread this halved the time compared with the same code using a runtime `d` loop: 3.75 ms vs 7.40 ms. For `d ≥ 16` it falls back to a runtime-length loop rather than compiling very long tuples.
4. **Each distance is computed once.** Only the lower triangle is computed (`i > j`), and the upper triangle is filled by copying it. This is exact, because `a - b == -(b - a)` in IEEE arithmetic, so the squares and therefore the distances are bitwise equal.
5. **Column-major writes.** The inner loop walks down column `j` (`D[i, j]` for `i = j+1:n`), so the stores are contiguous.
6. **Threads.** `Threads.@threads` splits the work by columns. Each task writes only its own columns, so there are no data races. The mirror pass reads the finished lower triangle and writes only the upper one. `D` is allocated with `undef`, because every entry is written.

**The results are unchanged.** The test checks `pairwise_dist_fast(X) == pairwise_dist(X)` (exact equality, not `≈`) for a 2000×3 matrix and several other shapes. This holds because the original's `sum` adds fewer than 16 elements strictly left to right, which is exactly what `sqdist` does. For `d ≥ 16`, Base's `sum` switches to a reassociated SIMD reduction, so for wide `X` the results agree only up to rounding.

## `@btime`, X = randn(2000, 3) (measured, Julia 1.13)

| version | threads | time | allocations |
|---|---|---|---|
| original | 1 | 279.0 ms | 24,000,003 (946 MiB) |
| fast | 1 | **3.52 ms** | 22 (30.6 MiB) |
| fast | 6 | **2.09 ms** | 72 (30.6 MiB) |

The speedup is about 80× on one thread and about 115× with six. Threads add relatively little because the remaining cost is mostly writing the 30.5 MiB result matrix to memory. If you can use only one triangle, for example by wrapping the result in `Symmetric`, or avoid materializing the n×n matrix at all, that saves more time than further changes to the arithmetic.
