```julia
"""
    mymul!(C, A, B; blocksize=128) -> C

Compute `C = A * B` for dense matrices of any numeric element type, using
cache-blocked loops in column-major order. `C` must not alias `A` or `B`.
"""
function mymul!(C::AbstractMatrix, A::AbstractMatrix, B::AbstractMatrix; blocksize::Integer = 128)
    Base.require_one_based_indexing(C, A, B)
    m, K = size(A)
    K2, n = size(B)
    K == K2 || throw(DimensionMismatch("A has size $(size(A)) and B has size $(size(B)): inner dimensions differ"))
    size(C) == (m, n) || throw(DimensionMismatch("C has size $(size(C)), expected ($m, $n)"))
    (Base.mightalias(C, A) || Base.mightalias(C, B)) &&
        throw(ArgumentError("output C must not share memory with A or B"))
    blocksize > 0 || throw(ArgumentError("blocksize must be positive"))
    bs = Int(blocksize)
    fill!(C, zero(eltype(C)))
    for jj in 1:bs:n, kk in 1:bs:K, ii in 1:bs:m
        jmax, kmax, imax = min(jj + bs - 1, n), min(kk + bs - 1, K), min(ii + bs - 1, m)
        for j in jj:jmax
            for k in kk:kmax
                b = B[k, j]
                # i ∈ ii:imax ⊆ 1:m, the checked row range of both A and C.
                @inbounds @simd for i in ii:imax
                    C[i, j] = muladd(A[i, k], b, C[i, j])
                end
            end
        end
    end
    return C
end
```

### Design

- **Loop order.** The outer three loops step through blocks (`jj`, `kk`, `ii`). Inside a block the order is `j → k → i`, so the innermost loop runs down a column of both `A` and `C`, which is contiguous in column-major storage. `B[k, j]` is loaded once and reused across the whole `i` loop. A 128×128 block of `A` (128 KiB for `Float64`) and the matching column strips of `C` stay in L2 cache while they are reused.
- **Generic element types.** The code works for any numeric element type. It accumulates with `muladd` into `C`, which starts from `zero(eltype(C))`, so `Int` and `Rational` results are exact. For `Float64` and `Float32`, `muladd` lets the compiler use fused multiply-add instructions.
- **Checks.** The inner dimensions must agree and `C` must be `m×n`; otherwise `DimensionMismatch` is thrown. If `C` aliases `A` or `B`, an `ArgumentError` is thrown, because writing into an input would corrupt the result.
- **`@inbounds @simd`, on the innermost loop only.** I measured it before keeping it: the same blocked loop without it took **80.6 ms** instead of 15.0 ms, because the bounds checks prevent vectorization. The indices are provably in range: `i ∈ ii:imax ⊆ 1:m`, and `k` and `j` come from ranges bounded by the checked sizes.

### Tests

```julia
using Test, LinearAlgebra, Random, BenchmarkTools
rng = Xoshiro(4)
@testset "mymul!" begin
    for (m, k, n) in ((1, 1, 1), (3, 5, 7), (64, 64, 64), (65, 130, 33), (200, 1, 200))
        A, B = randn(rng, m, k), randn(rng, k, n)
        @test mymul!(zeros(m, n), A, B) ≈ A * B
    end
    Ai, Bi = rand(rng, -9:9, 70, 90), rand(rng, -9:9, 90, 50)
    @test mymul!(zeros(Int, 70, 50), Ai, Bi) == Ai * Bi              # exact
    Ac, Bc = randn(rng, ComplexF32, 70, 90), randn(rng, ComplexF32, 90, 50)
    Cc = mymul!(zeros(ComplexF32, 70, 50), Ac, Bc)
    @test eltype(Cc) == ComplexF32 && Cc ≈ Ac * Bc
    Ar, Br = rand(rng, 1:9, 5, 5) .// 7, rand(rng, 1:9, 5, 5) .// 3
    @test mymul!(zeros(Rational{Int}, 5, 5), Ar, Br) == Ar * Br
    A = randn(rng, 10, 10)
    @test mymul!(zeros(10, 10), A, A; blocksize=3) ≈ A * A
    @test_throws DimensionMismatch mymul!(zeros(3, 3), randn(3, 4), randn(3, 3))
    @test_throws DimensionMismatch mymul!(zeros(3, 2), randn(3, 4), randn(4, 3))
    @test_throws ArgumentError mymul!(A, A, randn(10, 10))
    @test mymul!(zeros(4, 4), view(randn(8, 8), 1:4, 1:4), randn(4, 4)) isa Matrix
end
```

All 13 checks pass. They include exact equality for `Int` and `Rational`, `Complex{Float32}` (where the result's element type is preserved), sizes that are not multiples of the block size, a block size of 3, and views.

### Speed at n = 512 (measured, BenchmarkTools, Julia 1.13)

| | time | |
|---|---|---|
| `mymul!` Float64, blocksize 32 | 20.3 ms | |
| `mymul!` Float64, blocksize 64 | 17.0 ms | |
| `mymul!` Float64, **blocksize 128 (default)** | **15.0 ms** | 17.9 GFLOP/s |
| `mymul!` Float64, blocksize 256 | 18.6 ms | |
| `mul!` (OpenBLAS, 1 thread) | 5.3 ms | |
| `mul!` (OpenBLAS, 3 threads) | 2.0 ms | |
| `mymul!` `Int` | 28.3 ms | (`mul!` with Julia's generic integer matmul: 21.4 ms) |
| `mymul!` `Complex{Float32}` | 46.5 ms | (`mul!` with BLAS `cgemm`, 1 thread: 9.9 ms) |

On one thread, `mymul!` is about 2.8× slower than OpenBLAS for `Float64`. Most of the remaining gap comes from the inner loop: every fused multiply-add also loads and stores `C[i, j]`, so the loop is limited by memory traffic rather than arithmetic. BLAS uses a register-blocked micro-kernel that keeps a small tile of `C` in registers across the whole `k` loop and packs the panels of `A` and `B` into contiguous buffers.

As an experiment, I unrolled the inner kernel to update four columns of `C` for two values of `k` per pass. That reduced the time to 10.9 ms (about 1.4× faster), at the cost of about 40 more lines. To go further you would need a real micro-kernel with explicit SIMD vectors, for example through SIMD.jl or LoopVectorization.jl, or Octavian.jl, which implements all of this in pure Julia.
