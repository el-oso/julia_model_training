```julia
using LinearAlgebra: LinearAlgebra, UnitLowerTriangular, UpperTriangular, SingularException

"""
    lu_pp!(A) -> (L, U, p)

LU factorization with partial pivoting, overwriting the square matrix `A` so
that `A[p, :] == L * U` for the *original* `A`. `L` (unit lower) and `U` (upper)
are triangular views of the overwritten `A`. Throws `SingularException(k)` if no
nonzero pivot exists in column `k`. `eltype(A)` must be closed under division
(floats, complex, `Rational`, …); use [`lu_pp`](@ref) for integer matrices.
"""
function lu_pp!(A::AbstractMatrix)
    Base.require_one_based_indexing(A)
    n = LinearAlgebra.checksquare(A)
    p = collect(1:n)
    for k in 1:n
        # pivot: largest |A[i, k]| for i ≥ k
        piv = k
        amax = abs(A[k, k])
        for i in k+1:n
            a = abs(A[i, k])
            if a > amax
                amax, piv = a, i
            end
        end
        iszero(amax) && throw(SingularException(k))
        if piv != k
            for j in 1:n
                A[k, j], A[piv, j] = A[piv, j], A[k, j]
            end
            p[k], p[piv] = p[piv], p[k]
        end
        # multipliers, then rank-1 update of the trailing block, column by column
        akk = A[k, k]
        for i in k+1:n
            A[i, k] /= akk
        end
        for j in k+1:n
            akj = A[k, j]
            iszero(akj) && continue
            for i in k+1:n
                A[i, j] -= A[i, k] * akj
            end
        end
    end
    return UnitLowerTriangular(A), UpperTriangular(A), p
end

"""
    lu_pp(A) -> (L, U, p)

Non-mutating [`lu_pp!`](@ref). Integer matrices are factored in the type of
`one/one` (`Float64` for `Int`, exact for `Rational`).
"""
function lu_pp(A::AbstractMatrix)
    T = typeof(oneunit(eltype(A)) / oneunit(eltype(A)))
    return lu_pp!(copyto!(similar(A, T), A))
end

"""
    lu_solve(L, U, p, b) -> x

Solve `A x = b` given `A[p, :] == L * U`. Only the strict lower part of `L` and
the upper part of `U` are read (the unit diagonal of `L` is implied).
"""
function lu_solve(L::AbstractMatrix, U::AbstractMatrix, p::AbstractVector{<:Integer}, b::AbstractVector)
    Base.require_one_based_indexing(L, U, p, b)
    n = length(b)
    size(L) == size(U) == (n, n) && length(p) == n ||
        throw(DimensionMismatch("L, U must be $n×$n and p of length $n; got $(size(L)), $(size(U)), $(length(p))"))
    T = typeof(oneunit(eltype(U)) \ (oneunit(eltype(L)) * oneunit(eltype(b))))
    x = Vector{T}(undef, n)
    for i in 1:n
        x[i] = b[p[i]]
    end
    for j in 1:n                    # forward: L y = Pb, column-oriented
        xj = x[j]
        iszero(xj) && continue
        for i in j+1:n
            x[i] -= L[i, j] * xj
        end
    end
    for j in n:-1:1                 # back: U x = y, column-oriented
        iszero(U[j, j]) && throw(SingularException(j))
        x[j] /= U[j, j]
        xj = x[j]
        for i in 1:j-1
            x[i] -= U[i, j] * xj
        end
    end
    return x
end
```

### Design

- **Algorithm.** This is right-looking Gaussian elimination with row pivoting, which LAPACK calls `getf2`. At step `k` it picks the row with the largest `|A[i,k]|`, swaps rows, stores the multipliers `A[i,k] / A[k,k]` below the diagonal (that is `L`), and subtracts the rank-1 update from the trailing block.
- **Column-major loops.** In the update, `j` is the outer loop and `i` the inner one, so the innermost loop runs down contiguous columns: `A[i, j] -= A[i, k] * akj`. The multiplier computation and the forward and back substitution in `lu_solve` are written column-oriented the same way. The row swap necessarily runs across a row, but it is only O(n) per step.
- **Output without copies.** `lu_pp!` returns `UnitLowerTriangular(A)` and `UpperTriangular(A)`, which are views of the overwritten matrix, so `L * U`, `Matrix(L)` and similar operations work directly. `lu_solve` reads only the strict lower part of `L` and the upper part of `U`, so it also accepts plain dense `L` and `U`.
- **Generic element types.** Pivot selection uses only `abs`, `>` and `iszero`. With `Rational{BigInt}`, the factorization is exact: the tests check `A[p, :] == L * U` and `A * x == b` with `==`, not `≈`. `lu_pp` widens `Int` to `Float64`, using the type of `one/one`, so that the in-place division can be done.
- **Singularity.** `SingularException(k)` is thrown when column `k` has no nonzero pivot. For floating-point input this checks for an exact zero, the same as `LinearAlgebra.lu`. A nearly singular float matrix factors without error.
- **Shared rows.** For `Float64` input the pivots match LAPACK's (`p == lu(A).p` in the tests).

using Test, LinearAlgebra, Random
@testset "lu_pp" begin
    rng = Xoshiro(3)
    for n in (1, 2, 5, 50)
        A = randn(rng, n, n)
        L, U, p = lu_pp(A)
        @test A[p, :] ≈ L * U
        F = lu(A)
        @test p == F.p
        @test Matrix(L) ≈ F.L && Matrix(U) ≈ F.U
        b = randn(rng, n)
        @test lu_solve(L, U, p, b) ≈ A \ b
    end
    A = rand(rng, -5:5, 6, 6) .// 1 .+ 0 // 1
    A = Rational{BigInt}.(A)
    while det(Float64.(A)) == 0; A = Rational{BigInt}.(rand(rng, -5:5, 6, 6)); end
    L, U, p = lu_pp(A)
    @test eltype(L) == Rational{BigInt}
    @test A[p, :] == L * U                        # exact
    b = Rational{BigInt}.(rand(rng, -9:9, 6))
    x = lu_solve(L, U, p, b)
    @test A * x == b                              # exact
    Ai = rand(rng, -9:9, 8, 8)

### Speed vs `LinearAlgebra.lu` at n = 500 (measured, BenchmarkTools, Julia 1.13)

```
lu_pp(A)            9.34 ms   (6 allocations: 1.91 MiB)
lu(A), 3 BLAS thr   1.91 ms
lu(A), 1 BLAS thr   2.51 ms
max |A[p,:] - L*U|  4.3e-14  (LAPACK: 3.6e-14)
lu_pp, Rational{BigInt}, n = 40:  11.4 ms
```

Measured on one thread, `lu_pp` is about 3.7× slower than LAPACK. The reason is the algorithm, not bounds checking:
- **Bounds checks.** I tried `@inbounds @simd` on the inner update loop and it saved only 4% (8.94 ms vs 9.31 ms), so I left it out.
- **Blocking.** The remaining gap is because LAPACK's `getrf` is blocked: it factors a panel of columns and then applies the update as a matrix–matrix product (BLAS-3), which reuses data from cache. The unblocked version above streams the whole trailing matrix through memory once for every `k`.
- **Closing the gap.** To get closer you would need a recursive or blocked LU whose trailing update is a cache-blocked matrix multiply. That is a much bigger piece of code.
