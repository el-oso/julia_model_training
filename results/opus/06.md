`windows(v, k)` returns an iterator that yields each length-`k` window as a `view` of `v`, so nothing is copied. Summing over all windows of 10^7 elements took 72 ms with 0 allocations, about 4× faster than copying each window.

```julia
struct Windows{V<:AbstractVector,W}
    v::V
    k::Int
    function Windows(v::V, k::Integer) where {V<:AbstractVector}
        k > 0 || throw(ArgumentError("window length must be positive, got k = $k"))
        i = firstindex(v)
        W = typeof(view(v, i:i-1))     # every window has the type of this (empty) view
        return new{V,W}(v, Int(k))
    end
end

"""
    windows(v::AbstractVector, k::Integer)

Iterate over the `length(v) - k + 1` contiguous length-`k` windows of `v`,
each a `view` into `v` (no copying). Yields nothing when `k > length(v)`;
throws `ArgumentError` when `k ≤ 0`.
"""
windows(v::AbstractVector, k::Integer) = Windows(v, k)

Base.IteratorSize(::Type{<:Windows}) = Base.HasLength()
Base.length(w::Windows) = max(length(w.v) - w.k + 1, 0)
Base.eltype(::Type{<:Windows{V,W}}) where {V,W} = W

function Base.iterate(w::Windows, i::Int = firstindex(w.v))
    last = i + w.k - 1
    last > lastindex(w.v) && return nothing
    return view(w.v, i:last), i + 1
end
```

Notes:

- **No allocation per window.** Each window is `view(v, i:i+k-1)`, a small immutable `SubArray` that holds the parent array and a `UnitRange`. Because it does not escape the loop, the compiler keeps it on the stack. The tests check this: a `for w in windows(x, 16)` loop and `sum(sum, windows(x, 16))` both report `@allocated == 0`.
- **`eltype`.** At construction, the window type is taken from an empty view, `typeof(view(v, i:i-1))`. An empty view is valid for any vector, including an empty one, so this gives the exact `SubArray` type whatever `v` is (an `Array`, a view, an `OffsetArray`, …). That type is then stored as a type parameter. As a result `eltype` is concrete and `collect` produces a concretely typed `Vector`, without depending on what type inference happens to deduce.
- **`length` and `IteratorSize`.** `HasLength` together with `length = max(length(v) - k + 1, 0)` lets `collect` allocate the result once. If `k > length(v)` there are zero windows, and if `k ≤ 0` the constructor throws `ArgumentError`.
- **OffsetArrays.** Iteration runs from `firstindex(v)` to `lastindex(v)`, so offset vectors work. Each window is indexed `1:k`, because a view's axes come from the range used to index it.

### Tests

```julia
using Test, OffsetArrays
function f(x)
    s = 0.0
    for w in windows(x, 16)
        s += sum(w)
    end
    return s
end
g(x) = sum(sum, windows(x, 16))

@testset "windows" begin
    v = collect(1:5)
    @test collect(windows(v, 2)) == [[1, 2], [2, 3], [3, 4], [4, 5]]
    @test length(windows(v, 2)) == 4
    @test length(windows(v, 5)) == 1
    @test length(windows(v, 6)) == 0
    @test isempty(collect(windows(v, 6)))
    @test isempty(collect(windows(Int[], 1)))
    @test_throws ArgumentError windows(v, 0)
    @test_throws ArgumentError windows(v, -1)
    ws = collect(windows(v, 3))
    @test eltype(ws) == eltype(windows(v, 3))
    @test ws[1] isa SubArray
    v[2] = 20; @test ws[1] == [1, 20, 3]          # views, not copies
    o = OffsetArray([10, 20, 30, 40], -2:1)
    @test collect(windows(o, 2)) == [[10, 20], [20, 30], [30, 40]]
    @test length(windows(o, 2)) == 3
    @test eltype(collect(windows(o, 2))) == eltype(windows(o, 2))
    vv = view(collect(1:10), 2:2:10)
    @test collect(windows(vv, 2)) == [[2, 4], [4, 6], [6, 8], [8, 10]]
    @test sum(sum, windows([1.0, 2.0, 3.0], 2)) == 8.0
    s = "abc"; @test collect(windows(collect(s), 2)) == [['a','b'], ['b','c']]
    x = rand(1000)
    f(x)
    @test (@allocated f(x)) == 0
    g(x)
    @test (@allocated g(x)) == 0
    @test g(x) ≈ sum(sum(@view x[i:i+15]) for i in 1:length(x)-15)
end
```

All 20 checks pass.

### `sum(sum, windows(v, 16))` on 10^7 elements (measured, BenchmarkTools)

```julia
v = rand(10^7)
@btime sum(sum, windows($v, 16))                      # 71.7 ms (0 allocations: 0 bytes)

naive(v, k) = sum(sum(v[i:i+k-1]) for i in 1:length(v)-k+1)   # copies each window
@btime naive($v, 16)                                  # 316.3 ms (19999970 allocations: 1.79 GiB)
```

The view-based version is about 4.4× faster than copying each window, and it does not allocate. It still does O(n·k) work. If you only need window sums, a running sum is O(n), but it no longer gives you the windows themselves.
