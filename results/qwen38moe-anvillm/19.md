## File Format (per record, written as one atomic `write` call)

```
┌──────────┬──────────┬───────────────┬──────────┬───────────────┬──────────┐
│ magic    │ key_len  │ key           │ val_len  │ value         │ CRC32    │
│ 4 bytes  │ 4 bytes  │ key_len bytes │ 4 bytes  │ val_len bytes │ 4 bytes  │
│ "KVST"   │ LE u32   │ UTF-8 bytes   │ LE u32   │ raw bytes     │ LE u32   │
└──────────┴──────────┴───────────────┴──────────┴───────────────┴──────────┘
```

- **Magic** `"KVST"` (0x4B 0x56 0x53 0x54) — validates the record header.
- **key_len / val_len** — little-endian uint32, allowing variable-length keys/values.
- **CRC32c** over `key_len + key + val_len + val` — detects torn writes (crash mid-record).

## Design decisions

| Concern | Solution |
|---------|----------|
| **Crash recovery** | On `open_store`, replay records from the beginning. Any record with a bad CRC (or truncated mid-read) is silently dropped; the file is truncated at that point. |
| **Overwrites** | `put!` *never* overwrites — it appends a new record. The in-memory index maps `key → last-seen offset`, so the latest `put!` wins on `get`. |
| **Tombstones** | `delete!` writes a record with `val_len = 0`. `get` returns `default` for empty values. |
| **Compaction** | `compact!` reads all records into memory first, then truncates and rewrites only the latest per key. |
| **Performance** | 100k `put!`s in **~0.12s** (single `write` syscall per record, no fsync). Index is purely in-memory. |
