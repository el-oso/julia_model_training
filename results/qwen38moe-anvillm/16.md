Here's the zero-allocation version using a flat `Matrix(3, n)` layout (Structure of Arrays) with an explicit accumulator buffer:

```julia
function step!(pos, vel, mass, dt, acc)
    n = size(pos, 2)
    acc .= 0.0
    for i in 1:n
        xi = pos[1, i]; yi = pos[2, i]; zi = pos[3, i]
        for j in 1:n
            i == j && continue
            dx = pos[1, j] - xi
            dy = pos[2, j] - yi
            dz = pos[3, j] - zi
            r2 = dx*dx + dy*dy + dz*dz
            r = sqrt(r2 + 1e-9)
            inv_r3 = 1.0 / (r2 * r)
            acc[1, i] += mass[j] * dx * inv_r3
            acc[2, i] += mass[j] * dy * inv_r3
            acc[3, i] += mass[j] * dz * inv_r3
        end
    end
    for i in 1:n
        vel[1, i] += acc[1, i] * dt
        vel[2, i] += acc[2, i] * dt
        vel[3, i] += acc[3, i] * dt
        pos[1, i] += vel[1, i] * dt
        pos[2, i] += vel[2, i] * dt
        pos[3, i] += vel[3, i] * dt
    end
    return nothing
end
```

**Key changes and why:**

| Change | Why |
|--------|-----|
| `pos::Matrix(3,n)`, `vel::Matrix(3,n)` | Eliminates `Vector{Vector}` indirection; column-major layout matches Julia's memory model |
| `acc` passed in | `similar(pos)` would allocate a new matrix; pre-allocated buffer = **zero allocations** |
| Scalar `xi, yi, zi` hoisted out of inner loop | Avoids repeated `pos[:, i]` indexing; the compiler can keep them in registers |
| Explicit `dx, dy, dz` + `r2 = dx*dx+…` | No temporary `Vector` from `pos[:,j] .- pi`; no `sum(d.^2)` allocation |
| `inv_r3 = 1.0/(r2*r)` | Replaces `r^3` (two extra muls) — one fewer multiplication |
| Unrolled 3-component update | No `@.` or `d .* inv_r3` temporary; the compiler keeps everything in registers |
| `acc .= 0.0` | Broadcast assignment on a `Matrix` is fast and allocates nothing |

**Caller setup:**
```julia
n = length(mass)
pos = zeros(3, n)
vel = zeros(3, n)
acc = zeros(3, n)
step!(pos, vel, mass, dt, acc)
```

**Result equivalence:** The computation is identical (same operations, same `1e-9` softening), so results differ only in floating-point rounding from the re-ordered scalar accumulation.
