## Result — `windows.jl`

The `Windows` struct + iterator protocol produces **zero-copy** contiguous windows:

| Requirement | Status |
|---|---|
| `iterate` (zero-copy `@view`) | ✅ |
| `length` → `n - k + 1` | ✅ |
| `eltype` → `SubArray{eltype(V),1,V,...}` so `collect` works | ✅ |
| `IteratorSize` → `HasLength()` | ✅ |
| `for w in windows(v,k)` no per-window alloc | ✅ (3 total allocs = just the container vector) |
| `k > n` → 0 windows | ✅ |
| `k ≤ 0` → `ArgumentError` | ✅ |
| `OffsetArray` | ✅ |
| `sum(sum, windows(v,16))` on 10⁷ | ✅ **37.5 ms** |

Key design choices:
- **State** is the 0-based start index of the last yielded window. `iterate(w)` yields position 0 with state `0`; `iterate(w, i)` yields position `i+1` (0-based) with state `i+1`.
- **`eltype`** returns the `SubArray` type so `collect` infers `Vector{SubArray{...}}` (vector of views) rather than trying to coerce each view into a scalar.
- **`@view`** inside the module produces true `SubArray`s with `parent === v` — no copy.
