Done. Here's a summary of the final implementation:

**`parse_csv_line(line::AbstractString; delim=',') -> Vector{String}`**

| Requirement | How it's met |
|---|---|
| RFC 4180 quoting | State-machine scanner on `codeunits` (UInt8); `""` → skip-by-2, standalone `"` → closing quote |
| Unterminated quotes | `j > n` → `throw(ErrorException("unterminated quote"))` |
| No regex / no CSV.jl | `replace(raw, "\"" => "\"")` is a literal string replacement |
| UTF-8 fields | `line[start:stop]` on the original `AbstractString` handles all UTF-8 boundaries |
| 10⁶ lines/s | **1.32×10⁶** short-line throughput (~0.76 μs/line) |

**Key design decisions:**

1. **`codeunits` for scanning** — all special chars (`"`, `,`, whitespace) are ASCII (1 byte), so byte-position tracking is valid and fast.

2. **`""` skip-by-2, not greedy** — the scanner only advances past `""` when it's *not* at the string boundary; otherwise the second `"` is the closing quote (e.g. `""""` → empty field + closing, not unterminated).

3. **Delimiter skip after quoted field** — a comma immediately after `"` is the field-separator, not a new empty field (avoids spurious `["a", "", "c"]` → `["a", "c"]`).

4. **`last_was_delimiter` flag** — distinguishes "trailing empty field after delimiter" from "nothing left after closing quote at EOF".
