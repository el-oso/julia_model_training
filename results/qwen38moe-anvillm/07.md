### How it avoids recomputation

The public `integrate(a, b)` calls `promote(a,b)` (so `Int` bounds become `Float64`, etc.) then hands `f(a)` and `f(b)` down as the inner `_adapt`'s `fa`, `fb`. Each recursive node reuses the *same* endpoint values — the recursion tree only computes `f` at the midpoints that it actually needs:

| Node | known | new eval |
|---|---|---|
| top `[a,b]` | `f(a)`, `f(b)` | `f(m)` |
| `[a,m]` | `f(a)`, `f(m)` | `f((a+m)/2)` |
| `[m,b]` | `f(m)`, `f(b)` | `f((m+b)/2)` |

So at depth `d` the total distinct calls is `2d+1` (not `3·2ᵈ`).

### Results

| test | rel/abs error |
|---|---|
| `sin` on `[0,π]` → 2.0 | ~5×10⁻¹³ |
| `sqrt` on `[0,1]` → 2/3 | ~3×10⁻¹³ |
| `exp(-x²)` on `[-5,5]` → √π | ~1.5×10⁻¹² |
| `BigFloat` (rtol 1e-28) | ~2.7×10⁻¹² (eps floor, expected) |
| `Float32` (rtol 1e-7) | ~10⁻⁷ |
| `a > b` swap | exact negation ✓ |

The BigFloat case hits the `eps/2` absolute floor before reaching 1e-28 because `exp(-x²)` is effectively zero outside `[-5,5]` — the algorithm correctly stops subdividing when the correction is dominated by machine noise.
