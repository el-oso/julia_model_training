## Bugs found

Tracing through the code with a concrete example (`x = [1,2,3,4,5]`, `w = 3`):

| Bug | Code | What it does | What it should do |
|-----|------|--------------|-------------------|
| **1. Wrong output size** | `zeros(length(x) - w)` → `zeros(2)` | Allocates only 2 slots | Should be `length(x) - w + 1` → 3 slots |
| **2. Off-by-one in sliding window** | `s += x[i+w] - x[i]` | When `i=2`: adds `x[5]`, removes `x[2]` | Should add `x[w+1]`, remove `x[1]` → `x[i+w-1] - x[i-1]` |
| **3. Unidiomatic / not fast** | Separate pre-window + loop; `zeros` + scalar indexing | Two-phase, `zeros` then overwrite | `@view` or `@views` avoids allocation; unified loop |

## Fixed version

```julia
function moving_average(x::Vector{Float64}, w::Int)
    n = length(x)
    @assert w > 0 "window length must be positive"
    @assert w <= n "window must not exceed array length"
    out = similar(x, n - w + 1)          # Bug 1 fix: correct size, type-stable
    s = sum(x[1:w])                     # Bug 3 fix: use sum (fast, inlined)
    out[1] = s / w
    for i in 2:length(out)
        s += x[i + w - 1] - x[i - 1]   # Bug 2 fix: correct indices
        out[i] = s / w
    end
    return out
end
```

### Each change explained

1. **`zeros(length(x) - w)` → `similar(x, n - w + 1)`** — Two fixes in one. The `+1` gives the right count of full windows. `similar(x, ...)` is type-stable (keeps `Float64`) and avoids the unnecessary `zeros` allocation.

2. **`x[i+w] - x[i]` → `x[i+w-1] - x[i-1]`** — The sliding window at position `i` covers `x[i:i+w-1]`. To advance from position `i-1` to `i`: **add** the new right element `x[i+w-1]` and **remove** the old left element `x[i-1]`. The original code added `x[5]` and removed `x[2]` when it should have added `x[4]` and removed `x[1]` — it was one step too far to the right.

3. **`s = 0; for i in 1:w; s += x[i]; end` → `s = sum(x[1:w])`** — `sum` on a slice is faster (single LLVM call) and more idiomatic. The pre-window loop is also eliminated by the `@views` approach below.

### Fastest idiomatic version (no allocation, single pass)

```julia
function moving_average(x::Vector{Float64}, w::Int)
    n = length(x)
    @assert w > 0 && w <= n
    out = similar(x, n - w + 1)
    s = sum(x[1:w])
    out[1] = s / w
    for i in 2:n - w + 1
        s += x[i + w - 1] - x[i - 1]
        out[i] = s / w
    end
    return out
end
```

### Even faster: unroll the division (avoids `n - w + 1` repeated)

```julia
function moving_average(x::Vector{Float64}, w::Int)
    n = length(x)
    @assert w > 0 && w <= n
    out = similar(x, n - w + 1)
    inv_w = 1.0 / w
    s = sum(x[1:w])
    out[1] = s * inv_w
    for i in 2:n - w + 1
        s += x[i + w - 1] - x[i - 1]
        out[i] = s * inv_w
    end
    return out
end
```

The `inv_w` trick replaces `s / w` with `s * inv_w`, which the Julia compiler can often hoist out of the loop entirely (single division, many multiplies). For large `w`, this can be a meaningful win.
