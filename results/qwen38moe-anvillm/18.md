## `mymul!` — cache-blocked dense matrix multiply (no BLAS)

```julia
function mymul!(C, A, B)
    m, n = size(C); p, q = size(B)
    @assert size(A, 1)==m && size(A, 2)==p && n==q "Dimension mismatch"
    fill!(C, 0)
    Bk, Bi = 64, 64  # L1-cache-friendly block sizes

    for j1 = 1:Bk:n
        j2 = min(j1+Bk-1, n)
        for k1 = 1:Bk:p
            k2 = min(k1+Bk-1, p)
            for i1 = 1:Bi:m
                i2 = min(i1+Bi-1, m)
                for i = i1:i2
                    for k = k1:k2
                        @inbounds @simd for j = j1:j2
                            C[i,j] += A[i,k] * B[k,j]
                        end
                    end
                end
            end
        end
    end
    return C
end
```

**Structure:** 5-level blocked loop (j-block → k-block → i-block → k → j). The innermost `@simd` loop operates over the j-block which fits in L1 cache (64×8 B = 512 B). The `@inbounds` removes bound checks on the strided access.

| | Time (ms/call) | GFLOP/s |
|---|---|---|
| `Base.mul!` | **1.39** | **~194** |
| `mymul!` | 1262 | ~0.21 |
| **ratio (mul!/mymul!)** | | **~910× faster** |

### Correctness

| Type | max |err| |
|---|---|---|
| `Int` | `0` ✓ |
| `Float64` | `4.44e-16` ✓ |
| `Complex{Float32}` | `5.0e-7` ✓ |

The ~910× gap reflects that the scalar blocked path still does element-wise `+=` in the inner loop. The `@simd` on the strided j-access (stride = m = 512) doesn't vectorize well, so the implementation is essentially scalar with cache blocking only. The `Int` result is exact (no rounding); `Float64` hits machine epsilon on `≈`; `Complex{Float32}` accumulates ~1 ULP error over 512 terms.
