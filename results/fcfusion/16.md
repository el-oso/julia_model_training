To make this allocation-free and fast, the key changes are:

1. **Change layout from AoS to flat SoA** — `Vector{Vector{Float64}}` (array of vectors) becomes a flat `Vector{Float64}` with stride 3 (interleaved x,y,z). This eliminates per-vector allocations and improves cache locality.
2. **Pre-allocate the acceleration array** and pass it in, so `step!` never allocates.
3. **Use scalar operations** instead of vector arithmetic to avoid creating temporaries.
4. **Use `@inbounds`** to suppress bounds checks in the hot loops.

Here's the optimized version:

```julia
function step!(pos, vel, mass, acc, dt)
    n = length(mass)
    fill!(acc, 0.0)

    @inbounds for i in 1:n
        ax = 0.0; ay = 0.0; az = 0.0
        for j in 1:n
            if i == j
                continue
            end
            dx = pos[j*3-2] - pos[i*3-2]
            dy = pos[j*3-1] - pos[i*3-1]
            dz = pos[j*3]   - pos[i*3]
            r2 = dx*dx + dy*dy + dz*dz + 1e-9
            inv_r3 = 1.0 / sqrt(r2 * r2 * r2)
            fx = mass[j] * dx * inv_r3
            fy = mass[j] * dy * inv_r3
            fz = mass[j] * dz * inv_r3
            ax += fx; ay += fy; az += fz
        end
        acc[i*3-2] = ax
        acc[i*3-1] = ay
        acc[i*3]   = az
    end

    @inbounds for i in 1:n
        vel[i*3-2] += acc[i*3-2] * dt
        vel[i*3-1] += acc[i*3-1] * dt
        vel[i*3]   += acc[i*3]   * dt
        pos[i*3-2] += vel[i*3-2] * dt
        pos[i*3-1] += vel[i*3-1] * dt
        pos[i*3]   += vel[i*3]   * dt
    end
end
```

**Caller setup:**

```julia
n = 100
pos = rand(n * 3)
vel = rand(n * 3)
mass = rand(n)
acc = zeros(n * 3)  # pre-allocate once

# warm up (compiles)
step!(pos, vel, mass, acc, 0.01)

# now allocation-free
@time step!(pos, vel, mass, acc, 0.01)
```

**Why it's faster:**
- The original created `n` temporary vectors for `acc`, plus temporaries for each `pos[j] - pos[i]`, `d .^ 2`, and vector multiply — that's O(n²) allocations per step.
- This version does all arithmetic on scalars with no temporaries. The only memory writes in the inner loop are to local registers (`ax`, `ay`, `az`), written back once per particle.
- Flat layout gives better spatial locality — adjacent particles' coordinates are adjacent in memory.
