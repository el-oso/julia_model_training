**Why it's slow:**
- `acc = 0` is `Int`, but `x / 2` is always `Float64` (Julia's `/` operator returns Float64)
- On the first iteration, `acc` changes from `Int` to `Float64` — a **type change at runtime**
- Julia infers `acc::Union{Int64, Float64}`, so it must:
  - Box/unbox values on each iteration
  - Use dynamic dispatch instead of specialized machine code
  - Allocate on the heap instead of the stack

**The fix (one character change):**

```julia
function total(xs)
    acc = 0.0  # Float64 from the start
    for x in xs
        acc += x / 2
    end
    acc
end
```

Now `@code_warntype` shows `acc::Float64` consistently, and Julia generates optimal code with no type instability.
