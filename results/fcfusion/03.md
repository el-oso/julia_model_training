The implementation is complete and all tests pass. Here's a summary:

**File:** `evaluate.jl`

**Key design decisions:**
- **Grammar:** `expr → term ((+|-) term)*`, `term → unary ((*|/) unary)*`, `unary → - unary | power`, `power → atom (^ unary)?`, `atom → number | ( expr )`
- **Precedence:** `^` (right-associative) binds tightest, then unary minus, then `*`/`/`, then `+`/`-`. This gives `-2^2 == -4` and `2^-3 == 0.125`
- **Right-associativity of `^`:** `parse_power` calls `parse_unary` after `^` (not `parse_power`), which handles both right-associativity (`2^3^4 == 2^(3^4)`) and negative exponents (`2^-3`)
- **Number parsing:** Scans digits and at most one decimal point, then uses `parse(Float64, ...)` on the substring
- **Error handling:** Throws `ArgumentError` with the problem description and character position

**Test results:** All 30+ tests pass including edge cases (unbalanced parens, division by zero, invalid characters, whitespace handling) and the performance benchmark (10^5-character expression evaluated in ~67ms).
