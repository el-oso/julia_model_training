The function had two bugs. Here's what I fixed:

**Bug 1: Output size off-by-one**
- `zeros(length(x) - w)` → `zeros(n - w + 1)`
- For 5 elements with window 3, there are 3 full windows (positions 1-3, 2-4, 3-5), not 2.

**Bug 2: Wrong indices in the sliding update**
- `x[i+w] - x[i]` → `x[i + w - 1] - x[i - 1]`
- When sliding from window starting at `i-1` to `i`, you add the new rightmost element `x[i+w-1]` and subtract the old leftmost element `x[i-1]`.

**Performance/idiomatic improvements:**
- Stored `length(x)` in `n` to avoid repeated calls
- Explicit `s = 0.0` for type stability (avoids type promotion)
- The sliding window approach (O(n)) is already optimal for this problem

The output `[2.0, 3.0, 4.0]` is correct: the 3-window moving averages of `[1,2,3,4,5]`.
