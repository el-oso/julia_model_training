## What is slow

For every one of the 4 million `(i, j)` pairs the original allocates `X[i, :]`, `X[j, :]` (row slices copy), the difference, and the squared vector: 6 allocations per pair, 24 million in total, plus it computes both `D[i,j]` and `D[j,i]` and reads rows of a column-major matrix with stride `n`.

## Fast version

```julia
function pairwise_dist(X::AbstractMatrix)
    n, d = size(X)
    Xt = permutedims(X)                 # d x n: the coordinates of one point are contiguous
    T = float(eltype(X))
    D = zeros(T, n, n)
    for j in 1:n                        # upper triangle, column by column
        for i in 1:j-1
            s = zero(T)
            for k in 1:d
                δ = Xt[k, i] - Xt[k, j]
                s += δ * δ
            end
            D[i, j] = sqrt(s)
        end
    end
    for j in 1:n, i in j+1:n            # mirror; the diagonal stays 0
        D[i, j] = D[j, i]
    end
    return D
end
```

Changes and why:

1. **No allocations in the loop**: the squared distance is accumulated in a scalar over the `d` coordinates (3 here). `δ * δ` is what `.^2` computes (literal power 2 is `x*x`), and the summation order is the same as `sum` over a 3-element vector, so the results are bit-identical (checked below).
2. **Transposed copy `Xt`**: the `d` coordinates of one point become contiguous instead of `n` apart.
3. **Symmetry**: `D[i,j] == D[j,i]` exactly (since `(a-b)^2 == (b-a)^2` in floating point), so only the upper triangle is computed (half the arithmetic and `sqrt`s), then mirrored.
4. **Column-major traversal** (`j` outer, `i` inner) for the writes.
5. The output element type is `float(eltype(X))`; for `Float64` input this is the same as the original `zeros(n, n)`.

A multithreaded variant (no symmetry; each thread writes whole columns, so there are no overlapping writes):

```julia
function pairwise_dist_threaded(X::AbstractMatrix)
    n, d = size(X)
    Xt = permutedims(X)
    T = float(eltype(X))
    D = zeros(T, n, n)
    Threads.@threads for j in 1:n
        for i in 1:n
            s = zero(T)
            for k in 1:d
                δ = Xt[k, i] - Xt[k, j]
                s += δ * δ
            end
            D[i, j] = sqrt(s)
        end
    end
    return D
end
```

## Measurements (Julia 1.13.2, `X = randn(2000, 3)`, BenchmarkTools, pinned to 6 cores)

| version | time | allocations |
|---|---|---|
| original `pairwise_dist` | 237.1 ms | 24,000,003 (946 MiB) |
| scalar loops, no transpose, no symmetry | 16.5 ms | 3 (30.5 MiB) |
| + transposed copy | 11.6 ms | 6 |
| + symmetry (`pairwise_dist` above) | 9.3 ms | 6 (30.6 MiB) |
| threaded, 1 thread | 11.5 ms | |
| threaded, 4 threads | 4.4 ms | |
| threaded, 6 threads | 3.1 ms | |

All versions returned a matrix `==` to the original's (`maximum(abs, D - Dref) == 0.0`). So the serial version is about 25x faster and the 6-thread version about 75x. I also tried vectorizing over `i` with `@inbounds @simd` and a coordinate-outer loop; it was slower (13.7 ms without, 17.2 ms with `@simd`), so I did not use it. I did not determine why; I only know it did not help. The remaining time is on the order of writing a 30 MiB matrix, but I did not measure whether memory bandwidth is the limit.
