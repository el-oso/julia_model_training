## Layout

Replace the vectors of length-3 vectors (one heap object per particle, a pointer chase and an allocation for every `pos[j] - pos[i]`) with `3 × n` matrices: the three coordinates of one particle are adjacent in memory and the whole system is one contiguous array. Accelerations are never stored: the force on particle `i` depends only on the old positions, and `vel[:, i]` is not read by any other particle, so each `vel[:, i]` can be updated as soon as its acceleration is known. Positions must be updated only after all accelerations are done, so that is a second loop.

```julia
function step!(pos::AbstractMatrix, vel::AbstractMatrix, mass::AbstractVector, dt)
    n = length(mass)
    (size(pos) == (3, n) && size(vel) == (3, n)) ||
        throw(DimensionMismatch("pos and vel must be 3 × $n"))
    Base.require_one_based_indexing(pos, vel, mass)
    for i in 1:n
        xi, yi, zi = pos[1, i], pos[2, i], pos[3, i]
        ax = ay = az = zero(eltype(vel))
        for j in 1:n
            j == i && continue
            dx = pos[1, j] - xi
            dy = pos[2, j] - yi
            dz = pos[3, j] - zi
            r = sqrt(dx^2 + dy^2 + dz^2 + 1e-9)
            r3 = r^3
            m = mass[j]
            ax += m * dx / r3
            ay += m * dy / r3
            az += m * dz / r3
        end
        vel[1, i] += ax * dt
        vel[2, i] += ay * dt
        vel[3, i] += az * dt
    end
    for i in 1:n
        pos[1, i] += vel[1, i] * dt
        pos[2, i] += vel[2, i] * dt
        pos[3, i] += vel[3, i] * dt
    end
    return nothing
end

to_matrix(vs) = reduce(hcat, vs)        # Vector{Vector{Float64}} -> 3 × n
```

Same arithmetic as the original: `d = pos[j] - pos[i]`, `r = sqrt(sum(d.^2) + 1e-9)`, and `acc[i] += mass[j] * d / r^3` are done per component in the same order, so results agree (checked below; any difference is rounding). The `j == i` term is skipped as before.

I deliberately did not exploit the symmetry of the pairwise force (compute each pair once): it changes the summation order and needs an acceleration buffer; the straightforward loop is already allocation-free.

## Verification and timing

```julia
using Test, BenchmarkTools, Random

# original, for reference
function step_orig!(pos, vel, mass, dt)
    n = length(mass)
    acc = [zeros(3) for _ in 1:n]
    for i in 1:n, j in 1:n
        i == j && continue
        d = pos[j] - pos[i]
        r = sqrt(sum(d .^ 2) + 1e-9)
        acc[i] += mass[j] * d / r^3
    end
    for i in 1:n
        vel[i] += acc[i] * dt
        pos[i] += vel[i] * dt
    end
end

n = 200
rng = Xoshiro(1)
pos0 = [randn(rng, 3) for _ in 1:n]; vel0 = [randn(rng, 3) for _ in 1:n]; mass = rand(rng, n)
pos1, vel1 = deepcopy(pos0), deepcopy(vel0)
pos2, vel2 = to_matrix(pos0), to_matrix(vel0)
for _ in 1:10
    step_orig!(pos1, vel1, mass, 1e-3)
    step!(pos2, vel2, mass, 1e-3)
end
@test to_matrix(pos1) ≈ pos2 rtol = 1e-12
@test to_matrix(vel1) ≈ vel2 rtol = 1e-12
@show maximum(abs, to_matrix(pos1) - pos2)

step!(pos2, vel2, mass, 1e-3)
@test (@allocated step!(pos2, vel2, mass, 1e-3)) == 0

@btime step_orig!(p, v, $mass, 1e-3) setup = (p = deepcopy($pos0); v = deepcopy($vel0)) evals = 1;
@btime step!(p, v, $mass, 1e-3) setup = (p = copy($pos2); v = copy($vel2)) evals = 1;
```

Measured (Julia 1.13.2, `n = 200`, one step, BenchmarkTools, `evals = 1` with fresh state): original 3.39 ms with 400,002 allocations (15.3 MiB); new `step!` 199 µs with 0 allocations, about 17x faster. After 10 steps the two implementations' positions differ by exactly `0.0` (bit-identical on this input), and `@allocated step!(...)` is 0 after warm-up. I did not add `@inbounds`/`@simd`; I did not measure what they would give.
