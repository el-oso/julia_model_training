```julia
"""
    @memoize function f(x::T1, y::T2)::R ... end
    @memoize f(x::T1) = ...

Cache results of `f` in a `Dict` keyed by the tuple of arguments. The cache is
a `const` global of the calling module, typed `Dict{Tuple{T1,T2},R}` from the
argument and return annotations (`Any` where there is none). Recursive calls
go through the memoized function and so hit the cache.
"""
macro memoize(ex)
    if Meta.isexpr(ex, :(=)) || Meta.isexpr(ex, :function)
        sig, body = ex.args[1], ex.args[2]
    else
        error("@memoize: expected a function definition (`function f(...) ... end` or `f(...) = ...`)")
    end
    rettype = nothing
    if Meta.isexpr(sig, :(::), 2)
        sig, rettype = sig.args
    end
    (Meta.isexpr(sig, :call) && sig.args[1] isa Symbol) ||
        error("@memoize: only plain `f(args...)` signatures are supported (no `where`, no qualified names)")
    fname = sig.args[1]
    names = Symbol[]
    types = Any[]
    for a in sig.args[2:end]
        if a isa Symbol
            push!(names, a); push!(types, :Any)
        elseif Meta.isexpr(a, :(::), 2) && a.args[1] isa Symbol
            push!(names, a.args[1]); push!(types, a.args[2])
        else
            error("@memoize: unsupported argument `$a` (keyword, default, vararg and unnamed arguments are not supported)")
        end
    end
    cache = Symbol("#memo_", fname, "_", string(hash(sig), base=16))
    keytype = :(Tuple{$(types...)})
    valtype = rettype === nothing ? :Any : rettype
    fullsig = rettype === nothing ? sig : Expr(:(::), sig, rettype)
    key = Expr(:tuple, names...)
    # `get!` with a function re-looks-up the slot if the recursive calls
    # inserted into the dict (and possibly rehashed it).
    fbody = quote
        get!($cache, $key) do
            $body
        end
    end
    return esc(quote
        const $cache = Dict{$keytype,$valtype}()
        $(Expr(:function, fullsig, fbody))
    end)
end
```

## Fibonacci

```julia
@memoize fib(n::Int)::Int = n < 2 ? n : fib(n - 1) + fib(n - 2)

@show fib(90)           # 2880067194370816120
@assert fib(90) == 2880067194370816120
@show @allocated(fib(90))   # a cache hit
```

Annotating the return type matters: without `::Int` the dictionary's value type is `Any`, so each hit returns a boxed value and `fib` is not inferred as returning `Int`.

## Limitations

- Top level only: the cache is a `const` global in the calling module, so `@memoize` cannot be used on a function defined inside another function. The cache variable has a generated name (`#memo_fib_<hash>`) and there is no public handle to clear it; re-evaluating the same `@memoize` line in one session redefines the constant (which may warn or error depending on the Julia version).
- One cache per method definition (the name includes a hash of the signature), shared by all arguments of that method.
- Not supported: keyword arguments, default values, varargs, `where` clauses, unnamed arguments, and parametric method definitions. The macro stops with an error message in those cases.
- Arguments must be hashable with sensible `isequal` semantics. Mutable arguments are keyed by value hash/equality, so mutating an argument after the call can return stale results, and `1` and `1.0` are different keys (`isequal`), which means the typed key `Tuple{Int}` also forces `convert`. Functions with side effects, or results that depend on global state, will return stale values.
- The cache grows without bound and is not thread-safe: `Dict` must not be mutated from several tasks concurrently, so do not call memoized functions in parallel without your own locking.
- Typed keys help only when annotations are concrete; with abstract annotations (`x::Integer`) or none, keys are `Tuple{Integer}`/`Tuple{Any}` and lookups box.
- A `return` inside the body returns from the cached closure, which is fine, but `@memoize` changes stack depth: very deep recursion uses two frames per level.

Run results (Julia 1.13.2): `fib(90)` returns `2880067194370816120`, `@inferred fib(10)` passes, a cached `fib(90)` call allocates 0 bytes, and a two-argument annotated method (`g(x::Int, y::Float64)`) and an unannotated one (`h(x) = x + 1`) both work.
