Done. **`rle.jl`** (plus `Project.toml`/`Manifest.toml` for the test-only `OffsetArrays` dependency) — 53/53 tests pass, benchmark on 10⁷ elements: `rle` ~20–35 ms, `unrle` ~30 ms.

**Design**

- **`rle(v::AbstractVector) → (Vector{eltype(v)}, Vector{Int})`** — single pass over `eachindex` (so views, negative strides, and `OffsetArray`s work with no special-casing). Preallocates `n` slots, then shrinks with `resize!` (O(1) on shrink — no copy). No `push!`, no `prev` sentinel.
- **`unrle(values, counts) → Vector{eltype(values)}`** — validates length match + non-negative integer counts (clear `ArgumentError`s), preallocates the exact output, one fill loop.
- **`iseq(a, b)`** — the run-equality predicate: `===` first (fast path, catches `missing === missing`), then a `T<:AbstractFloat` method that treats `NaN` runs as one run, then `(a == b) === true` so `missing == x → missing` can never reach a boolean context.

**Verified**
- `missing`, `NaN` (incl. distinct NaN payloads via `parse(Float64, "NaN")`, `Float16`), empty inputs, sub/strided/reversed views, `OffsetArray` (negative *and* positive offsets), `String`/`Bool`/`Union{Missing,Int}`/heterogeneous `Any`.
- Type stability: `@inferred` tests plus `Base.return_types` checks — concrete return types for every concrete input, including the generic `AbstractVector` path (`Tuple{Vector{Any}, Vector{Int}}`).
- Full 10⁷-element roundtrip asserted (`w == v`).

**Notes**
- `==` on arrays containing `missing`/`NaN` isn't `true` (Julia semantics), so roundtrip tests use `isequal` — documented in the docstring.
- Two JET warnings remain on `unrle` (e.g. `1:c` "may get `Missing`"): false positives — the guard throws before the loop can see a `Missing` count, which a test pins down. JET just can't propagate the guard's effect.
