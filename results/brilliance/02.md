## Deliverables

**`LRUCache.jl`** — the cache, Base only (`import Base: ...` is the only import):

- `LRU{K,V}(capacity)` — a `Dict{K, node}` for O(1) lookup plus a doubly linked list of nodes for O(1) reordering/eviction (`head` = MRU, `tail` = LRU). Values are stored in a concrete `value::V` field, so no boxing and the hot path is fully monomorphic.
- `get(cache, key, default)` — hit promotes to MRU via pure pointer surgery (unlink + push-front): **zero heap allocations** on hits *and* misses, verified with `@allocated == 0`.
- `setindex!` / `cache[key] = value` — insert or update, always promotes to MRU; a new key in a full cache evicts the LRU entry in O(1) (tail unlink + `pop!` on the dict). `capacity == 0` stores nothing.
- `haskey` — O(1), does **not** count as a use (spec requirement, explicitly tested).
- `length`, `isempty`, `size`, plus idiomatic extras: `getindex`, `get(f, cache, key)`, `empty!`, MRU-first `iterate`/`keys`/`values`, `show`.

**`test/runtests.jl`** — 16,694 assertions covering: basic API, read/write recency, misses and `haskey` not refreshing, updates not growing the cache, eviction order, heterogeneous `V`, capacity zero, `empty!`, iteration order, zero-allocation checks, a 5,000-op randomized test against a reference model (exact values + exact recency order after every op), and an O(1) scaling check.

## Verification highlights

- **Type stability** (via `code_warntype`): `get`/`setindex!`/`getindex` infer `Body::Int64`, `haskey` `Body::Bool` — no `Any`/`#undef` anywhere; the compiler narrows the node after the `=== nothing` check and sees `node.value::Int64` directly.
- **O(1) empirically**: steady-state insert+get throughput at 4× the working set is within ~1.4× (memory effects), vs the ≥4× that O(n) eviction would require.
- **Julia gotcha solved along the way**: in this harness, defining `setindex!`/`get` without an explicit `import Base.X` creates shadow functions instead of extending `Base` — so `cache[key] = value` (which dispatches to `Base.setindex!`) silently fails. The module uses the standard `import Base: get, setindex!, ...` pattern, which I confirmed empirically extends the Base methods.
